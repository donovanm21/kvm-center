# v5.50 — public-release readiness plan

**Goal:** ship kvm-center as a stable, secure, low-friction public product. Today the codebase is homelab-validated and trips over a small set of foundational issues that don't matter in a single-operator LAN but do matter when strangers run it. This plan groups those issues into a tractable sequence of PRs.

Source: five parallel multi-agent audits run after v5.49.8 (backend stability, SPA UX, security + demo threat model, public-codebase hygiene, deployment friction). 85+ findings consolidated below; full per-finding detail captured per-PR.

**Priorities (operator stated, in order):** stability, security, user experience.

## Top three blockers

These are foundational and must land before any public flip:

1. **Agent management surface is unauthenticated.** `/command`, `/storage-upload`, `/storage-file`, `/self-update` on the agent's `:8081` accept any LAN peer with no token, no mTLS, no HMAC. Combined with `/api/telemetry` accepting unauthenticated host registration on the server side, a same-LAN attacker can register a host, redirect operator commands to their own listener, or hijack an existing host on a single telemetry tick.
2. **Server↔agent channel is plain HTTP and the agent skips TLS verify.** Every operator action (commands, storage uploads, console secrets) crosses the management LAN in cleartext; agents accept any TLS cert at all. MITM is trivial.
3. **Demo `admin` reaches `/api/admin/restore` and `/api/admin/restart`** with attacker-supplied tarballs. Demo CA private key persists across the daily reset. One POST exfiltrates the cluster CA.

PRs `O-AGENT-AUTH` (1+2) and `D-DEMO-LOCKDOWN` (3) below land these. Everything else is staged after.

## What's deliberately excluded from this plan

- Docker-publish CI/CD speedup (cross-compile + native arm64) — parked per operator decision; tracked separately.
- Appliance-build supermin failure (issue #64) — needs infra-level decision (self-hosted runner with `/dev/kvm`).
- Hub repo public flip — operator action; banner removal queued for after the flip.
- Tag-per-deploy backfill — cosmetic; can land alongside any release.
- Kubernetes / Helm chart — flagged as a gap by the deployment audit but is out of scope for v5.50; gets its own minor release.

## Execution

Autonomous execution against this plan starts immediately after this file lands. Memory entry at `project_v5.50_release_readiness.md` tracks per-PR status so progress survives any context compaction. The operator review happens via the final completion summary; no per-PR checkpoints.
